# Running same-period blocks on Rivanna

ConTree blocks were lost to `/tmp` wipes, image-cache eviction and GitHub clone
rate-limiting. On Rivanna the 100 v2.4 task SIFs are prebuilt on scratch, each episode gets
its own 4-CPU/16 GB Slurm allocation, and nothing needs to be cloned or cached. The DSH arm
runs the same `contree/run_task_contree.py` driver with `--sandbox apptainer`; the native
arm runs `run_native_episode.py`. Both open the sandbox through `apptainer.open_sandbox`,
so images, preflight, thread settings and grading are shared.

## What differs from a ConTree block

| | ConTree | Rivanna |
| --- | --- | --- |
| Tasks | `data/kokkos/SWE-kokkos-bench-v2`, verifier regenerated by `prepared_kokkos_tasks` | published v2.4 payload; its verifier is already guarded and `load_guarded_task` refuses one that is not |
| Sandbox | 4 vCPU / 4 GB, pinned to 2 CPUs, serial verifier build | 4 CPUs / 16 GB, four build threads (the v2.4 leaderboard envelope) |
| Grader / sandbox timeout | DSH 2400 s, native 1200 s / 3600 s | 2400 s for both arms / 7200 s |
| Network in sandbox | off | off |

Scores are therefore not comparable with ConTree blocks or with each other across
datasets. Combine only within-block deltas from Rivanna blocks.

## Layout on Rivanna

| Path | Contents |
| --- | --- |
| `/scratch/fad3ew/openhands-smoke/genesis-cookbook` | git clone of `science-rl`; each block takes a detached worktree |
| `.../dsh-iteration/tasks/` | 100 v2.4 payloads, each with `environment/sif.path` |
| `.../dsh-iteration/dsh-runtime/` | DSH 0.2.0-rc.2 `node_modules` shared by every block |
| `.../v24-release-20261002/images/` | the task SIFs (about 106 GB); do not rebuild |
| `.../dsh-blocks/<block>/` | one block: `code/`, `design.json`, slot lists, `runs/`, `logs/` |

## Budgets

Blocks start from a named budget in `tinker_cookbook/recipes/kokkos_rl/budget.py`. New blocks
default to `long-250` (250 requests; see `notes/pi_harness/BUDGET.md`); pass
`--budget-profile v2.4` to reproduce the frozen 40-request benchmark. Single keys can be
overridden with `--budget key=value`, and an arm can run under another budget with
`budget=<profile>`, e.g. `--arm native40="native budget=v2.4"`. Long budgets need a longer
Slurm limit: `DSH_TIME=04:00:00 bash .../launch_block.sh ...`.

## Run a block

```bash
ssh login.hpc.virginia.edu
B=/scratch/fad3ew/openhands-smoke; R=$B/genesis-cookbook
git -C $R fetch -q origin && git -C $R checkout -q origin/science-rl
BLOCK=$B/dsh-blocks/block-r01
mkdir -p $BLOCK && git -C $R worktree add --detach $BLOCK/code origin/science-rl
cd $BLOCK/code
$B/.venv/bin/python -m notes.dsh_inkling.harness.rivanna.block plan $BLOCK \
  --tasks-root $B/dsh-iteration/tasks --env-file $B/inkling-eval.env \
  --dsh-runtime $B/dsh-iteration/dsh-runtime --draws 4 \
  --arm native=native --arm control= --arm state=--state-target
bash notes/dsh_inkling/harness/rivanna/launch_block.sh $BLOCK 36 2
```

`launch_block.sh` first submits a job that hashes every SIF into `sif-sha256.json`; the
episode arrays start only after it succeeds, and each episode re-checks its SIF against
that digest. Episodes are never rerun: an existing output directory makes the slot refuse.

Monitor with `python -m notes.dsh_inkling.harness.rivanna.block status $BLOCK`, then
analyse:

```bash
python -m notes.dsh_inkling.block_report --drop-infra \
  --arm native=$BLOCK/runs/native-d0,$BLOCK/runs/native-d1,... \
  --arm control=$BLOCK/runs/control-d0,... --arm state=$BLOCK/runs/state-d0,...
```

The trust gate from the handoff still applies: every arm keeps about 90% of its episodes
and native scores about 45-50, or the cross-arm result is discarded.

## Episode evidence

Each `runs/<arm>-d<draw>/results/<task>/` holds `slot.json`, `config.json`, `summary.json`,
`candidate.patch`, `grading.json`, and for DSH also `preflight.json`, `events.jsonl`,
`proxy-budget.jsonl` and `dsh.patch.yml`. Native episodes add `attempts.jsonl` (infra
retries) and the transcript. `harness_status` `exit_1` for DSH means the request cap was
reached; the candidate is still graded, as in the reference.

## Known pitfalls

1. The shared venv has an editable install of an old checkout; the block runner always
   imports from `BLOCK/code`.
2. `apptainer/1.5.0` cannot pull (`proot: ptrace(TRACEME)`); the scripts load `1.4.5`.
3. Never pass a `taskset` CPU list inside a Slurm allocation; the runner passes
   `--cpu-affinity none`.
4. `kokkos__kokkos-8182`'s verifier build is the known systemic timeout; it stays in the set.
